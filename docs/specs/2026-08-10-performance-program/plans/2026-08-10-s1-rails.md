## Scope and design anchors

- R1 interaction probes remain in the four existing owners. There is no
  central interaction coordinator (`program-design.md:113-128`). Each owner
  exposes the reviewed `beginInteraction(kind, correlationId)` /
  `settleInteraction(correlationId)` observation seam, with superseded ids
  excluded from latency (`program-design.md:629-640`).
- R2 adds only the Specification-defined Repo Explorer outline-apply proxy:
  apply-call invocation through return, with row-count context
  (`program-design.md:134-141,641-642`). It does not claim to measure native
  SwiftUI diff completion.
- R3 is a pure headless query in `scripts/` plus a mise task. It adds no writer,
  stored state, telemetry lifecycle, or app launch (`program-design.md:143-152,620-627`).
- R4 stays inside the SwiftSyntax architecture-lint registry, with stable ids
  and report-only severity (`program-design.md:154-158`).
- R5 lives beside the existing high-volume-source guidance in `CLAUDE.md`
  (`program-design.md:159-160`).
- Allowed edges and privacy boundaries are fixed: controller → performance
  recorder; report → loopback Victoria APIs; lint registry → diagnostics; no
  content, raw path, or UUID telemetry (`program-design.md:170-174`).

## Explicit non-goals

- No terminal, git, forge, Repo Explorer, startup, renderer, animation, or
  interaction hotspot fix.
- No change to product state, command routing, focus behavior, layout behavior,
  persistence, vendor code, trace-tag selection, stable tracing defaults, or
  OTLP source-scrubbing policy.
- No native SwiftUI outline-diff-completion claim; the R2 proxy ends when the
  app-owned outline apply call returns.
- No new telemetry lifecycle, completion record, database, cache, dashboard,
  external service, or report-side app launch.
- No shell/regex architecture lint and no lint becomes blocking in slice 1.
  R19 blocking flips belong to later slices after the relevant surface is
  cleaned.

## Owner-confirmed V1 gates — 2026-08-10

The gates are relative to the active display refresh interval, so proof records
the refresh interval used for each marker-scoped run and reports work-settle
duration in both milliseconds and frames. Presentation animation triggered by
the settled terminal state is excluded from the work window; R23 governs the
animation.

| Interaction | Owner-confirmed gate | Normative measured unit |
|---|---:|---|
| command bar open | work-settle p95 ≤ 2 frames; p99 ≤ 4 frames | invoking key-down/click → presented, focused, initial results published and settled |
| command bar close | work-settle p95 ≤ 2 frames; p99 ≤ 4 frames | non-executing dismissal input → removed, prior focus restored and settled |
| tab move | work-settle p95 ≤ 2 frames; p99 ≤ 4 frames | reorder commit input → final strip order with moved pane still presented and settled |
| divider drag | ≤ 1 frame per admitted sample | one coalesced input sample → its published layout frame |
| Cmd+R | work-settle p95 ≤ 2 frames; p99 ≤ 4 frames | command key-down → management-layer target state published and settled |

The branch must also be at-or-better than the immediately preceding completed
baseline window for every interaction. These numbers and boundaries are
owner-confirmed 2026-08-10; changing them requires a new reviewed plan meaning.

## False-green risks and stop/replan conditions

- Settling at command return, state assignment, or animation start is a false
  green; settlement must come from the owner terminal-publication callback.
